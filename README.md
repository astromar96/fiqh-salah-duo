# منهاج المسلم — تطبيق تعلّم

تطبيق تعلّم بأسلوب دويلينجو على كتاب **«منهاج المسلم»** لأبي بكر جابر
الجزائري (دار السلام، الطبعة الرابعة)، يغطّي أبواب الكتاب الخمسة.
يعمل على **iOS و Android والويب** من قاعدة كود واحدة عبر Expo.

الأسئلة والشروح مكتوبة لهذا التطبيق، وليست نقلًا لنصّ الكتاب؛ وتحت كل
سؤال رقمُ صفحته في المطبوع للرجوع إلى الأصل.

## التشغيل

```bash
npm install

npm run web        # المتصفح
npm run ios        # محاكي iOS
npm run android    # محاكي Android
```

أول تشغيل على جهاز أو محاكٍ يحتاج توليد المشروع الأصلي:

```bash
npx expo prebuild          # ينشئ ios/ و android/ (غير ملتزمة في git)
```

### ملاحظة على إعداد Android في هذا الجهاز

متغيّرا البيئة `ANDROID_HOME` و`ANDROID_SDK_ROOT` يشيران إلى مسارين مختلفين،
و`ANDROID_SDK_ROOT` يشير إلى مسار غير موجود، فيفشل Gradle برسالة
«Several environment variables … contain different paths to the SDK».
إمّا تحذف `ANDROID_SDK_ROOT` من ملف إعداد الصدفة، أو تشغّل البناء هكذا:

```bash
env -u ANDROID_SDK_ROOT npm run android
```

### بناء الويب للنشر

```bash
npm run build:web    # يُخرج موقعًا ثابتًا في dist/
```

## المنهج

أبواب الكتاب الخمسة كاملةً، على ترتيب الكتاب نفسه. الجدول مُولَّد من
المحتوى بـ `node scripts/curriculum-table.mjs`، فلا يتخلّف عنه:

| الباب | الصفحات | وحدات | دروس | أسئلة |
|---|---|---|---|---|
| الباب الأول — العقيدة | ٧–٥٨ | ٦ | ٤٧ | ٣٥٤ |
| الباب الثاني — الآداب | ٥٩–١١٤ | ٧ | ٥٦ | ٤٤٨ |
| الباب الثالث — الأخلاق | ١١٥–١٤٦ | ٤ | ٣٢ | ٢٤٧ |
| الباب الرابع — العبادات | ١٤٧–٢٦٧ | ٢٣ | ١٤٦ | ١١٣٤ |
| الباب الخامس — المعاملات | ٢٦٩–٤٤٠ | ٢١ | ١٦٩ | ١٣٣٤ |
| **المجموع** | **٧–٤٤٠** | **٦١** | **٤٥٠** | **٣٥١٧** |

داخل كل باب وحدات، وداخل كل وحدة دروس. الفتح متسلسل **داخل الباب وحده**،
فكل باب يُبدأ من أوّله مهما كان حال غيره، ويفتح الباب على أوّل درس لم يُنجز.

ترتيب الوحدات في الباب مأخوذ من `source.pages[0]`، لا من المعرّفات، فلا
يلزم أن تكون أرقام الوحدات على ترتيب الكتاب. ووحدات كل باب تغطّي صفحاته
كلَّها بلا فجوة، و`npm run content:check` يرفض التداخل والخروج عن المجال.

## أنواع العناصر

ستة أنواع، كلّها في `src/engine/types.ts`:

```jsonc
{ "t":"info",  "h":"العنوان", "b":"نص تعليمي", "src":147 }
{ "t":"mcq",   "q":"السؤال", "o":["أ","ب","ج"], "a":1, "e":"الشرح", "src":147 }
{ "t":"tf",    "q":"العبارة", "a":true, "e":"الشرح", "src":148 }
{ "t":"order", "q":"رتّب", "items":["أولًا","ثانيًا"], "e":"الشرح", "src":151 }
{ "t":"match", "q":"وصّل", "pairs":[["أ","١"],["ب","٢"]], "e":"الشرح", "src":151 }
{ "t":"fill",  "q":"جملة فيها ____ فراغ", "bank":["أ","ب"], "a":"أ", "e":"الشرح", "src":152 }
```

`src` إلزامي: رقم الصفحة في المطبوع، ويُتحقَّق من وقوعه ضمن صفحات الوحدة.

## تعديل المنهج

1. عدّل ملف الوحدة في `src/content/units/`، وفيه `section` يحدّد بابها.
2. `npm run content:check` — يتحقق من البنية والمفاتيح والتكرار ومجال الصفحات.
3. `npm run content:build` — يعيد توليد `src/content/index.ts`.

`content:build` يرفض التوليد إن وجد خطأ، فلا يُبنى التطبيق على محتوى معطوب.

## معاني الكلمات

نصّ الكتاب فصيحٌ مشكول، وفيه مصطلحاتٌ فقهية وألفاظٌ لا يعرف كلُّ قارئٍ
معناها. فتحت كل سؤالٍ صندوقٌ يشرح ما ورد فيه من ذلك بعربية سهلة، وما استجدَّ
منها في التفسير يُذكر في لوحة التغذية الراجعة حيث ينظر القارئ وقت الكشف.

المعجم **مركزيّ**: ملفٌ واحد فيه الكلمة ومعناها، والعارض يلتقطها في أي نصٍّ
وردت فيه. فتُشرح الكلمة مرّةً وتظهر في كل موضعٍ منها، ولا يُؤشَّر على ٣٥١٧
سؤالًا واحدًا واحدًا.

```jsonc
{ "w": "الرُّبوبيَّة", "m": "أنَّ الله وحده هو الخالق المالك المدبِّر لكل شيء" }
{ "w": "المِيراث",    "m": "ما يُقسَم من مال الميت على أهله", "also": ["التوريث"] }
```

**المطابقة على الهيكل المجرَّد** من التشكيل، إذ النصّ مشكول بالكامل ولا يحمل
المعجم كلَّ احتمالات الشكل للكلمة الواحدة. ثم تُقتطع السوابق واللواحق فتطابق
الكلمةُ معرَّفةً ومنكَّرة، ومعها واوُ العطف وباءُ الجرّ وضميرُ الغائب وألفُ
تنوين النصب: «بالصلاة» و«صلاتُه» و«شأنًا» كلُّها تَصل إلى مدخلتها. وتُفضَّل
أطولُ عبارةٍ تطابق، فـ«فرضُ كفايةٍ» مصطلحٌ واحد لا كلمتان.

وللاقتطاع خطؤه، إذ يَردّ كلمةً إلى غير أصلها: «وسلَّم» من «صلَّى الله عليه
وسلَّم» تؤول إلى عقد «السَّلَم»، و«فِعله» إلى «العِلَّة»، و«بعدها» إلى
«العِدَّة». ولا يُفرِّق بينها وبين الصواب رسمٌ ولا قاعدة، فلها قائمة `never`
تمنع هذه الصور من المطابقة رأسًا.

وما تشابه رسمُه بعد التجريد ولم يكن أحدُ معنييه أولى تُجمع دلالاته في مدخلةٍ
واحدة ويختار القارئ بالسياق — كـ«المُحرِم» و«المَحرَم» و«المُحرَّم».

```bash
npm run glossary:check          # البنية والتعارض والتغطية وحالات المطابقة
FORMS=60 npm run glossary:check # ومعها الصور التي لم تُطابَق إلا باقتطاع
```

المدقّق يستورد `src/engine/gloss.ts` نفسه، فلا تتفرّع نسختان من المطابقة.
وهو يَرفض المدخلة التي يبدأ معناها بتكرار كلمتها — لأنها تُعرض بعدها —
ويكشف الصيغة التي تستحوذ عليها مدخلةٌ أخرى فلا تُطابَق أبدًا. وفيه حالاتٌ
محروسة، كلُّ سطرٍ منها خطأٌ وقع مرّةً أو صوابٌ عزيزٌ يَسهل كسره.

تغطية المعجم الآن: **٣٦٨ مدخلة**، تشرح كلمةً فأكثر في **٩٥٪** من العناصر،
بمعدَّل ٣٫٣ كلمة للعنصر الواحد.

## آليات اللعب

- **قلوب**: خمسة، ينقص واحد بكل خطأ، ويعود قلب كل ٢٠ دقيقة.
- **نقاط**: ١٠ لكل إجابة صحيحة، و٢٠ مكافأة لإتمام الدرس بلا خطأ.
- **سلسلة**: تزيد بيوم تمرين، وتنقطع بتخطّي يوم.
- السؤال الخاطئ يعود لآخر الطابور حتى يُجاب صحيحًا.
- الحفظ في `AsyncStorage`، ويُرفع إلى الحساب إن كان القارئ داخلًا.
- تحت كل سؤال معاني كلماته الصعبة — انظر «معاني الكلمات» أعلاه.

## الحساب ومزامنة التقدّم

التقدّم يُحفظ على الجهاز أوّلًا، فالتطبيق يعمل بلا شبكة وبلا حساب. ومتى دخل
القارئ حسابًا رُفع تقدّمه إلى Firestore ونزل إليه ما سجّلته أجهزته الأخرى.

| الطريق | الويب | iOS | Android |
|---|---|---|---|
| ضيف | ✅ | ✅ | ✅ |
| بريد وكلمة مرور | ✅ | ✅ | ✅ |
| Google | ✅ | ✅ | ✅ بمفتاح التنقيح |
| Apple | — | ✅ | — |

**الضيف حسابٌ كامل** (مجهول في Firebase)، فتقدّمه يُزامَن كذلك. وربط مزوّدٍ
به بعدُ يُبقي المعرّف نفسه والوثيقة نفسها، فلا يضيع ما لعبه قبل الربط.

**الدمج تراكمي**: لا يُسقط درسًا منجزًا ولا يُنقص نقطة، فإعادة تطبيقه بلا
أثر، ومن ثَمّ يستقرّ الجهازان على حالة واحدة مهما تداخل ترتيب وصول
التحديثات. والنقاط تؤخذ بالأكبر لا بالجمع، إذ الجمع يضاعف ما سُجّل على
الجهازين معًا. ومحو التقدّم هو الاستثناء، فيُكتب إلى السحابة قبل أن تردّه
لقطةٌ تالية.

**المخزن المحلّي مفتاحه الحساب** (`fiqhSalahDuo.v3.<uid>`)، فجهاز يستعمله
حسابان لا يرث أحدهما تقدّم الآخر. وما لُعب قبل الدخول يتبنّاه أوّل حساب
يدخل ثم يُفرَغ المخزن العام، ومخزن النسخة السابقة يُرحَّل مرّة واحدة.

**قاعدة الحماية** في Firestore سطر واحد: `/users/{uid}` لا يقرؤه ولا يكتبه
إلا صاحبه. وما عداه مغلق.

### ما يلزم لإتمام الباقي

- **Apple على الويب وAndroid**: يحتاج Services ID ومفتاحَ خادم من حساب
  مطوّري Apple المدفوع، ثم وضعهما في مزوّد Apple بوحدة تحكّم Firebase. حتى
  ذلك الحين يظهر زرّ Apple على iOS وحده.
- **Apple على iOS**: إضافة `expo-apple-authentication` تضيف صلاحية «Sign in
  with Apple» إلى المشروع الأصلي، وهي لا تُوقَّع بحساب مطوّر مجّاني. فإن
  تعثّر بناء الجهاز لهذا السبب فاحذف الإضافة من `app.json`.
- **Google على Android في بناء الإصدار**: المسجَّل الآن بصمة مفتاح التنقيح
  وحده، فيُضاف SHA-1 مفتاح الإصدار في إعدادات تطبيق Android.
- **مفاتيح المشروع** في `src/lib/firebase.ts` معرّفات علنية لا أسرار: التطبيق
  ثابت يُخدم من صفحات GitHub فأيّ زائر يقرؤها من الحزمة. الحماية في قواعد
  Firestore وفي قائمة النطاقات المصرّح لها بالدخول. ولمن ينسخ المستودع أن
  يصل مشروعه هو بمتغيّرات `EXPO_PUBLIC_FIREBASE_*`.

## الاتجاه من اليمين لليسار

الاتجاه مضبوط **صراحةً** في كل مكوّن (`flexDirection: 'row-reverse'`،
و`writingDirection: 'rtl'` في `Txt`)، ولا نستعمل `I18nManager.forceRTL`
ولا `dir="rtl"` على مستند الويب. السبب: `forceRTL` يحتاج إعادة تشغيل
التطبيق على الأجهزة، و`dir` على المستند يعكس صفوف `row-reverse` مرة ثانية
فتختلف الواجهة بين الويب والأجهزة. الضبط الصريح يجعل المنصّات الثلاث متطابقة.

## ملاحظة فقهية

المادة تتبع تقسيم «منهاج المسلم» ومصطلحاته هو — وقد تخالف ما اشتهر في بعض
المذاهب في عدد الفروض أو تسمية الأركان. المحتوى للتدريب والمراجعة،
وللمسائل الخلافية وما يُعمل به يُرجع إلى أهل العلم.

## حقوق الكتاب

الأسئلة والشروح في `src/content/` مكتوبة لهذا التطبيق، وما نُقل بنصّه فهو
آيات وأحاديث. رقم الصفحة إحالة إلى المطبوع لا اقتباس منه، والكتاب نفسه
ليس في هذا المستودع ولا يُوزَّع معه.

## لاحقًا (غير منفّذ)

- مراجعة متباعدة (spaced repetition) للأسئلة المخطئة عبر الدروس
- اختبار سريع لفتح وحدة كاملة
- نطق صوتي للأذكار والأدعية
